# 博客文章（中文）

**标题备选**
- 我把 48 位哲学家做成了 Claude Code 技能，然后让他们互相辩论
- 一个合格的哲学家 AI，应该知道自己不知道什么

**适合平台：** 少数派、知乎、即刻、V2EX

---

我想问尼采怎么看我的创业项目。不是那种读过维基百科摘要的聊天机器人，而是一个按他的方式论证、引用他真正写过的书、并且拒绝对 1889 年之后的事情发表意见的东西。

于是我写了 48 个这样的角色，做成 [Claude Code 技能](https://github.com/BhackerJ/ai-philosophers)。每个角色就是一个 Markdown 文件。下面是我学到的几件事。

## 一、假引文才是真问题

大模型很擅长"哲学家腔"，而这种流畅恰恰是危险所在。随便问一个角色要句名言，它会给你一句自信、通顺、但从来没人写过的话。

所以每个角色带两份清单。一份**核实过的引文**，出处精确到章节："己所不欲，勿施于人。——《论语·卫灵公》"。一份**常见误传**："'选择你热爱的工作，你就一天也不用工作'——不在《论语》里，也不在任何早期文献里。"规则很简单：只逐字引用第一份清单，其他一律改述；用户引用第二份清单里的话时，礼貌纠正。

我把自己最没把握的 35 条引文拿去对照原始文献核了一遍，12 条需要修改。三分之一的错误率，而且都是我原本以为肯定没错的句子。误传是怎么扩散的，可见一斑。

## 二、"不知道"是功能，不是缺陷

最初的规则是"不知道你死后发生的事"。这是必要的，但不够，因为模型还是会把现代词汇当成自己的母语来用。

真正管用的规则是：*用户提到你身后的事物时，不要装懂。请对方描述一下，然后用你自己的原则，和你自己那个世界的类比来推理。*

问伊本·赫勒敦（14 世纪北非历史学家）：一家公司从车库里五个朋友起家，现在有 400 人、豪华办公室，创始人之间却不说话了，这是怎么回事？他会说自己没听过"公司"这个词，请你解释，然后诊断为：一个部落的 asabiyya（群体凝聚力）在艰苦中锻造，在奢侈中瓦解。说实话，诊断是对的。

## 三、有意识地出戏

第一版写着"永不出戏，永不承认是 AI"。我在想象有人对叔本华说"我不想活了"之后，把这条删了。

现在每个角色在两种情况下会放下角色：用户真诚地问"我是在和 AI 说话吗"，以及用户看起来真的处于困境中。第二种情况下，它会以一个人的身份回答，并引导对方去寻求现实中的帮助。这一条有专门的测试用例。

## 四、辩论比独白更能暴露真相

`/symposium kant mill 撒谎在任何情况下都是错的吗？` 会读取两个角色文件，然后组织一场辩论：开场陈述、两轮点名反驳、结束陈词，最后由中立的主持人总结双方真正的分歧在哪。

第一次运行时，康德主动提起了他 1797 年那篇关于"门口的杀人犯"的文章，密尔回应说："我说的是'几乎'，这个词承担了我全部答案的重量。"这两句都不在角色文件里，是模型在约束之内推理出来的。

## 五、像测试软件一样测试它

Claude Code 可以对插件跑评测。十个用例覆盖：是否保持角色口吻；是否装懂现代事物；被真诚追问时是否承认是 AI；遇到困境是否出戏；是否纠正误传引文；是否用用户的语言回答；辩论是否真有两方。每次运行只花几美分，每次改动都能测。
